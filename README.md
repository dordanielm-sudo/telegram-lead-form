# טופס לידים ל-Telegram

עמוד יחיד (`index.html`) שרץ כ-Telegram Mini App: לקוח לוחץ על כפתור בבוט,
משאיר שם וטלפון, והפרטים נשלחים לוובהוק ב-Make. אין שרת, אין build, אין
תלויות — קובץ אחד שצריך רק אחסון עם HTTPS.

## מה נשלח ל-Make

בקשת `POST` עם שני שדות בלבד, כ-form-encoded:

```
name=דנה כהן&phone=0541234567
```

הטלפון מנורמל לספרות (עם `+` בתחילתו אם הוזן קידומת בינלאומית). בסנריו ב-Make:
מודול **Custom webhook** → *Determine data structure* → שולחים ליד בדיקה אחד
מהטופס, ו-Make ילמד את שני השדות. אין צורך במודול Webhook response.

הכתובת נמצאת בראש ה-`<script>` שבתוך `index.html`, במשתנה `WEBHOOK_URL`.

## הקמה

### 1. אחסון

טלגרם דורש HTTPS עם תעודה תקפה. הדרך הקצרה היא GitHub Pages:

Settings → Pages → Source: **Deploy from a branch** → Branch: `main` / `root`
→ Save. אחרי דקה הכתובת היא:

```
https://<user>.github.io/telegram-lead-form/
```

(כל אחסון סטטי אחר עובד באותה מידה — Netlify, Cloudflare Pages, או תיקייה
בשרת קיים.)

### 2. הבוט (BotFather)

1. `/newbot` — או בוט קיים.
2. `/newapp` → בוחרים את הבוט → **Web App URL** = הכתובת מהשלב הקודם.
3. `/setmenubutton` → הכפתור שפותח את הטופס בתוך הצ'אט.

## הערות

- **הכתובת של הוובהוק גלויה בקוד המקור של העמוד.** כך זה בכל טופס סטטי:
  הדפדפן חייב לדעת לאן לשלוח. המשמעות היא שמי שמוצא אותה יכול להזרים לידים
  מזויפים. אם זה קורה בפועל, הפתרון הוא שרת קטן שמקבל את הטופס, מאמת מול
  טלגרם (`initData` חתום בטוקן של הבוט) ורק אז מעביר ל-Make.
- הבקשה נשלחת ב-`mode: "no-cors"`, כדי שהיעדר כותרות CORS בתשובה של Make לא
  יציג שגיאה על ליד שנמסר בפועל. המחיר: העמוד לא יכול לדעת אם Make החזיר
  שגיאה — ההיסטוריה של הסנריו ב-Make היא מקור האמת.
- העמוד עובד גם בדפדפן רגיל (בלי טלגרם): הטופס נשלח, פשוט אין חלון לסגור
  ואין מילוי מראש של השם.
